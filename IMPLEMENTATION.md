# Implementation and release readiness

The v1 library, CLI, schemas, Astro/Starlight renderer, neutral sample, self-hosted documentation, Git hooks, CI matrix, and release workflow are implemented. The repository started empty. The public repository is [miki-open-source/doc-base](https://github.com/miki-open-source/doc-base). The source is published. The [Quality workflow](https://github.com/miki-open-source/doc-base/actions/workflows/ci.yml) checks Linux, macOS, and Windows on Node 22 and 24, plus packed consumers and browser tests. Registry publication and repository/npm protections remain external release requirements below.

The repository uses pnpm 12.11.2 with a frozen workspace lockfile in CI. Use Node.js 22.12+ for the library and a current Node 22 or 24 release for repository tooling; `.nvmrc` selects 24. Astro and Starlight compatibility is declared in package peers and checked by doctor. TypeScript 6 is selected because the ESLint TypeScript tooling’s supported range does not yet include TypeScript 7.

## Supported installation layout

pnpm, npm, and Yarn with `nodeLinker: node-modules` are supported. Yarn Plug’n’Play rendering currently fails to resolve imports in the generated Astro configuration. The required Yarn setting and Astro’s corresponding troubleshooting guidance are documented in the quick start. No package manager is invoked during normal dev, validate, or build commands.

## External release requirements

1. Require all quality jobs before merge, protect version tags, enable private vulnerability reporting, and require approval for the npm-release environment.
2. Confirm ownership/availability of the six public npm package names and configure trusted publishing for this repository’s release workflow. Review the documented moderate dependency advisory before approving publication.
3. Repository/homepage/issue metadata points to miki-open-source/doc-base. Host the canonical schema URLs before release. The schema IDs come from the supplied specification; this local implementation does not provision the doc-base.dev domain.
4. Review the coordinated changelog and version, run the approved release workflow, and retain its per-package publish report and registry-install/build verification. No npm package has been published by this task.

The release script uses pnpm to publish the inspected tarballs with provenance, verifies the checked-out tag and coordinated versions, records partial success, and verifies the registry-installed CLI with an actual initialized production build. A partial publish must be documented and repaired with a new version; published versions must never be overwritten.
